# 0.7.1 — search matching and source/download latency

Date: 2026-10-27. versionName 0.7.1 / versionCode 11.

## What is complete

- Search normalizes Unicode width, case, whitespace and punctuation. `spiderman`, `Spider-Man` and bounded English typos can match titles already obtained from the catalogue. Matching remains title based, keeps `source + externalId` records distinct, and enforces years and issue numbers. WordPress/GetComics itself is not claimed to provide global typo search; the app ranks bounded local/remote candidates after retrieval.
- The service searches saved catalogue records when offline and preserves usable matches if some online requests fail. It uses a conservative remote prefix retry for an empty English result, a bounded three-request plan and explicit page continuation. Chinese aliases cover 15 common terms such as 内战/Civil War and X战警/X-Men. Every alias is marked `COMMON`; this release has no verified Chinese publisher/ISBN title evidence, so a hit does not mean a licensed Chinese edition or Chinese正文 exists. See [Chinese alias evidence](chinese-search-aliases.md).
- A recent verified source inspection can be reused for up to ten minutes when article URL, source version metadata, strong ETag, length, page count and modified time still match. Opening the reader still performs a live Range discovery and compares ETag/length before showing a page. A failed live open invalidates only the matching stale inspection. Cold opening remains bounded and may still be slow on a source requiring article parsing, redirects and archive indexing.
- Explicit full downloads now use a streaming Range transfer with up to a 16MiB network window and at most a 64KiB body buffer. Each response is checked for 206, Content-Range, exact Content-Length, strong ETag, identity encoding, truncation and overrun before the window advances the durable checkpoint. A failed window is rolled back. If a source rejects a range larger than the original 4MiB limit, one bounded fallback uses 4MiB; 200/full responses, permission failures and ETag changes never retry around the error. The ordinary page reader remains subject to its original 4MiB Range limit.

## X-Men by Jonathan Hickman Omnibus (2022)

The GetComics article is post `286362`, and its normal `/dls/` candidates point to Pixeldrain, Terabox, MEGA, MediaFire and WeTransfer. The user-provided Pixeldrain screenshot shows the service's own message: a 6.00GB free daily transfer allowance has already reached 6.65GB. That is a source-side quota, not the app's 500MB temporary cache and not a 1.1GB archive-size rejection. The app cannot and must not bypass it. The free-tier page says to return after the limit resets; the exact reset time zone is not established here. A normal authorized account/Premium plan or an independently reachable permitted source is required.

Before the screenshot, bounded host checks obtained 8,174 bytes of article metadata and no comic bytes. Pixeldrain info/share requests were reset before an HTTP response; MediaFire returned 403 without a verified public download button. No full archive was downloaded, no CAPTCHA/login was bypassed, and no alternative source is claimed ready. The UI now preserves a source-specific Pixeldrain message instead of implying phone storage is the cause.
