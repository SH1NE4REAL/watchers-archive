# 0.6.0 — clean reader and explicit whole-book downloads

Date: 2026-10-27. APK versionCode 8 / versionName 0.6.0.

## User-visible changes

The reader no longer shows cache hits, transferred bytes, storage figures, cache-clearing actions, logs or debugging. Its controls contain page position, navigation, bookmarks, the existing optional translation action, loading and necessary recovery actions. Protocol failures become readable messages. Storage management remains on the settings screen. Test server addresses and fixtures are hidden behind a debug-only long press on the version label.

GetComics details offer an explicitly confirmed whole-book download, using Wi-Fi by default. Downloaded titles enter the default shelf. Settings offers download management, pause/continue and a separate confirmed deletion action. Opening a completed book uses the private local archive directly, including when its remote URL is unavailable. Download removal preserves catalogue records, shelf membership, progress, bookmarks and notes; an active reading lease prevents archive deletion.

## Storage, networking and Android integration

- Offline files, durable partial downloads and small checkpoint records live in `filesDir/watchers-archive-phase1/offline-downloads`. They are user-requested persistent content, separate from the fixed **500,000,000-byte** disposable page/cover cache. Cache clearing never walks this directory. Downloads use normal available phone storage and reserve an additional 64MiB before writing.
- Each HTTP chunk is at most 4MiB, using the existing strict Range206/Content-Range/length/strong-ETag checks. A server ignoring Range still has its complete response refused. Offsets and file sizes are Long. No whole-book byte array or image expansion is introduced.
- Each accepted chunk is fsynced before its durable checkpoint is atomically replaced. Interrupted tail bytes are discarded on recovery. Full completion uses a same-directory rename; a crash between final rename and metadata commit is recoverable. Incomplete files are never offered for reading. CRC/image limits remain enforced when pages are read.
- Hashed names and the private directory prevent title/path traversal. OS locks plus in-process reader/writer leases protect download, replacement and removal. An already completed different version is retained until explicit removal.
- WorkManager 2.10.0 provides persistent unique tasks, constrained network/storage scheduling and foreground dataSync notifications. Work input contains only the comic ID. Blocking IO and cancellation are connected through the repository to the actual Range connection. Only network failures retry automatically, with exponential backoff from 30 seconds and at most three total attempts. Cancellation retains a durable resumable checkpoint.
- The merged Manifest includes foreground-service/dataSync and notification permissions. Android13+ notification permission is requested only after the user confirms a download. Refusing notification permission does not grant any file access. The app neither scans phone personal files nor copies a SAF-imported local archive into its download store.

It also covers ignored Range and malformed ranges with zero body consumption, truncation, changed ETag, cancellation/resume, crash-tail recovery, unavailable storage for a virtual 3GiB asset without creating that file, reader leases, concurrent stores and safe removal. Android host tests use real BitmapFactory, repository integration and WorkManager with a controlled fake task. UI tests check explicit download consent/default Wi-Fi and absence of reader diagnostics.

Legacy Robolectric SQLite extraction encountered a Windows DLL access failure. The WorkManager tests use Robolectric native SQLite and explicitly initialize the test scheduler; this tests the Android database implementation rather than masking it with a fake database. APK source compilation is distinct from connected-device execution.

## Chinese reading alternatives (design advice, not implemented here)

The recommended next interaction is a one-toggle Chinese overlay: retain OCR bounding boxes and image dimensions, translate bounded current/next-page text, and place reversible Chinese text regions in the same zoom/pan transform as the original image. It eliminates per-page dialogs. A later explicit whole-book pretranslation job can prepare text/coordinates after download, retaining original artwork and guarding its own memory/storage budget. Masking OCR rectangles does not guarantee correct speech-bubble boundaries or professional lettering; low-quality detections need an original-text fallback.

Existing Chinese editions imported by the user offer their original translation/typesetting. Optional cloud OCR/translation may improve some cases but requires an explicit upload choice, a service-side credential boundary, network and cost handling. The existing device model is intended for casual translation; artistic fonts, names and reading order remain quality risks. This release does not claim image-level Chinese typesetting, cloud translation or actual phone OCR quality.
