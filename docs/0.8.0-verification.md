# 0.8.0 — personal book names and automatic download-source selection

Date: 2026-10-28. Package `org.watchersarchive.app`, versionName `0.8.0`, versionCode `12`.

## User behavior

- Long-press a shelf cover, choose “修改书名”, enter a personal name and save. “恢复原名” removes the override. The label is used on shelf covers, search results, article details, reader titles and download status. Details retain the original name when different. Existing imported books do not need to be reimported.
- Personal names are keyed by stable comic ID in a separate atomic persistent Properties file. Original title, source URL, SAF URI, archive filename, membership, bookmarks and progress are not renamed or moved. Source refresh and temporary cache cleanup cannot overwrite these names. Search considers both original and personal names.
- “下载整本” queues discovery itself in WorkManager. The background task first resumes an existing compatible source, then, if necessary, discovers and tries up to 12 distinct source entries. It skips quota/access/HTML/expired/unsupported sources and advances after remote failures. Disk-space, file-use and local write failures stop the job. Cancel stops the entire source-selection and transfer operation.
- A source with a correct `206` response and strong ETag uses the bounded streaming Range/resume path. A normal file with a known length can instead use a user-requested full HTTP200 download without requiring online random access. That path streams with at most a 64KiB buffer, restarts from zero after interruption and uses a local version token if no strong remote ETag exists. It never pretends to support resume without an immutable remote version.
- Every production download must pass the local archive parser, index, first-page CRC, image limits and Android BitmapFactory checks before completion. HTML/JSON pages are rejected, and known RAR5/solid/encrypted/split headers are rejected early to avoid wasting a full transfer. The ordinary online reader continues to reject HTTP200 rather than silently downloading an entire archive.

## Source adapters and limits

Normal public redirects, Pixeldrain's allowed file API and successful public MediaFire pages with a genuine `downloadButton` are supported. MediaFire targets must remain on its official download hosts. Login/CAPTCHA/challenge/premium-required pages are not automated. A `/file_premium/` path alone is not treated as proof of a paid gate; the actual public page is inspected.

MEGA, Terabox, WeTransfer and other share workflows can be discovered but are not claimed to have complete automated adapters. If they require browser operations or have no verified public file link, the task records this and tries another source. Unknown-length responses are not accepted as arbitrary unbounded files. Mirrors are tied to their URL/version/length and are never spliced together. Switching may restart a file, and an unsupported or damaged candidate can require a different mirror.

Pixeldrain reaching a free allowance does not by itself prove all downloads are forbidden: the user's earlier screenshot also offered a limited-speed path. The resolver attempts a publicly permitted file even if its API announces a speed limit; only explicit refusal is treated as a source limit. Connection resets do not get mislabeled as quota evidence. This release does not rotate identities, bypass limits or create account sessions.

## Storage and migration

The existing `500,000,000` byte disposable page/cover budget is unchanged. Explicit download files/partials and personal names remain outside it. Existing Range-mode archive keys and legacy metadata are preserved; new mode fields default to Range for older records. A queued discovery request has zero known size and can never recover as an empty completed archive. Completion/rename recovery retains only validated file checkpoints; incomplete full responses are not promoted.
